## 사용자 요청

> "한 번의 요청이 처리되는 과정"에서 컨텍스트 내부를 도표로 처리해 준 것은 잘한 것이다. 이를 유지하고 토글을 이용해서 하네스가 만드는 컨텍스트 내부(즉, LLM이 보는 내용)를 어떻게 구성해서 LLM 에 전달하는지 실제 구조를 파악하게 해줘

## AI 응답 요약

기존 컨텍스트 막대 도표를 유지한 채, 그 아래에 "하네스가 꾸려 보내는 컨텍스트 펼쳐 보기" 토글을 추가했다. 단계마다 누적되는 system·tools·messages 구조를 "구조로 보기"와 "API 요청으로 보기"(Messages API 형식을 줄인 JSON) 두 방식으로 보여 주고, 이번 단계에 추가된 메시지를 강조했다.

## 수행 작업

- 단계별로 messages 끝에 덧붙는 assistant(text·tool_use)·user(tool_result) 메시지 데이터 정의(기존 위젯의 예시 내용을 그대로 사용)
- 블록 보기: 막대 도표와 같은 색 범주로 각 블록 구분, 역할(user/assistant)·tool_use id·tool_result 짝 표시, 새 메시지 강조
- JSON 보기: system·tools·messages 요청 본문을 표시하고 새 메시지 배경 강조
- 토글 열림 상태와 보기 방식을 단계 이동 사이에 유지, 새 내용이 보이도록 자동 스크롤
- 상태 비저장 재전송, 도구 결과가 user 자리에 들어감(프롬프트 인젝션), system-reminder 삽입, 프롬프트 캐싱·특수 토큰 직렬화 설명과 단순화 표기 추가
- 절 소개 문단에 토글 안내 추가
