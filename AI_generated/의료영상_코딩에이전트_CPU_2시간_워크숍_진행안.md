# 의료영상 딥러닝을 코딩 에이전트와 함께 만들기

## 2시간 워크숍 진행안 — 개인 노트북 CPU 실습

### 1. 개요

- **대상:** 병원 근무 의사. Python·딥러닝 경험이 없어도 참여 가능
- **목표:** 코딩 에이전트에게 작은 의료영상 분류기를 단계별로 구현하도록 지시하고, 생성된 코드와 결과를 의료 연구자의 관점에서 검토한다.
- **산출물:** 개인별 Python 작업 폴더 1개. 단계별 스크립트(`01_inspect_data.py` 등)와, 스크립트가 저장한 손실 곡선·혼동행렬·오분류 사례 그림 파일이 담긴다.
- **실습 자료:** [Kaggle PneumoniaMNIST classification](https://www.kaggle.com/datasets/pgibiostat/pneumoniamnist-classification)의 NumPy 배열 파일(`.npz`). 참가자가 파일을 직접 받지 않고, **Antigravity에게 다운로드와 데이터 점검을 요청**한다. 파일명·키 이름과 용량은 사전 준비 때 직접 확인한다. 28×28 흑백 흉부 X선 영상 5,031장. 학습 3,883장, 검증 524장, 시험 624장. 레이블은 1이 폐렴, 0이 정상이다. 시험 624장 중 폐렴은 390장(62.5%)이다.
- **실습 환경:** 개인 노트북의 VS Code(터미널), Python, 코딩 에이전트(Antigravity). Jupyter 노트북은 쓰지 않고 `.py` 스크립트를 터미널에서 실행한다. GPU를 요구하지 않는다.
- **학습 범위:** 교육용 영상 분류 실습. 학습된 분류 모델을 진료 의사결정 도구로 다루지 않는다.

### 2. 학습 목표

참가자는 종료 시 다음을 할 수 있다.

1. 영상 데이터의 크기, 레이블, 학습·검증·시험 분할을 확인한다.
2. 코딩 에이전트에게 작업을 작은 단계로 지시하고 코드 실행 결과를 확인한다.
3. 합성곱 층, 손실함수, epoch, 과적합을 실습 결과에 연결해 설명한다.
4. 혼동행렬에서 폐렴 민감도와 특이도를 읽고, ‘무조건 폐렴’ 기준선과 비교해 정확도의 한계와 오분류의 의미를 설명한다.
5. 28×28 영상과 제한된 평가 자료에서 얻은 수치를 임상 성능으로 일반화할 수 없는 이유를 말한다.

### 3. 진행자 사전 준비

**행사 전**

- 프롬프트 ①의 다운로드 방식(`kagglehub`)이 실제 행사 환경에서 되는지, Kaggle 계정·토큰 없이 받아지는지 미리 시험한다. 되지 않으면 참가자 안내문에 Kaggle 로그인과 토큰 준비 절차를 추가한다. 받은 파일의 파일명, 배열 키, 배열 크기(학습 3,883·검증 524·시험 624)가 이 진행안과 일치하는지 확인한다. 병원망 등 네트워크 제약에 대비해 교육 현장에서 합법적으로 배포 가능한 파일 제공 방법(USB, 내부 공유)을 예비로 준비한다. Kaggle 사본과 MedMNIST 원본(총 5,856장, 학습 4,708장으로 분할이 다름)의 원 출처·라이선스 문구를 확인해 안내하고, 두 자료의 수치를 섞어 쓰지 않는다.
- 사용할 Python 환경에 `numpy`, `matplotlib`, `scikit-learn`, `torch`, `kagglehub`를 설치하고 데이터 읽기부터 시험 평가까지 같은 유형의 **CPU 기기**에서 한 번 실행한다. 행사 당일 패키지 설치를 실습 시간에 포함하지 않는다.
- Antigravity와 VS Code 터미널 연결을 확인하고, 프롬프트 ①로 다운로드부터 배열 점검까지 미리 실행해 에이전트가 어떤 스크립트를 만드는지 본다. 그림은 화면에 띄우지 않고 파일로 저장하게 하므로(`matplotlib`의 `savefig`), 창을 띄울 수 없는 환경에서도 되는지 함께 확인한다.
- 완성된 진행자용 백업 스크립트 묶음을 준비한다. GPU가 필요한 사전학습 모델이나 원본 고해상도 X선 데이터는 사용하지 않는다. 참가자가 결과를 볼 수 없을 때를 대비해 백업 스크립트의 **실행 결과(콘솔 출력 텍스트와 그림 파일)**도 함께 배포한다.
- 작은 CNN은 합성곱 층 2개, 채널 수 16·32 정도, 배치 크기 64, **5~10 epoch**를 권장한다. 28×28 입력의 작은 모델이라 CPU에서도 epoch당 수 초~수십 초로 예상되지만, 사전 리허설에서 실제 시간을 재어 총 학습이 5분 안에 끝나는 epoch 수로 확정한다. 손실 곡선에서 학습·검증 손실의 벌어짐(과적합)을 볼 수 있으려면 epoch가 최소 5 이상이어야 한다. 난수 시드를 고정해 참가자 간 결과 차이를 줄인다. 무거운 패키지 업데이트와 모델 가중치 다운로드는 피한다.
- CPU 속도가 매우 느린 기기에 대비하여 **학습 자료에서만** 레이블별로 균형 있게 일부를 뽑는 대체 경로를 준비한다. 검증과 시험 자료는 그대로 두고 축소 학습의 한계를 설명한다.

**참가자 안내문**

> 워크숍 시작 전에 Python·VS Code·Antigravity를 준비하세요. 데이터는 워크숍에서 Antigravity에게 요청해 내려받습니다. 개인 노트북의 CPU로 실행합니다. Kaggle 토큰 등 비밀번호·키는 에이전트 대화창에 붙여 넣지 않습니다. 실제 환자 영상이나 환자정보는 에이전트에 입력하지 않습니다.

### 5. 참가자용 단계별 프롬프트

**① 데이터 다운로드와 점검 — 10분대 (Antigravity에게 요청)**

> Kaggle 데이터셋 `pgibiostat/pneumoniamnist-classification`(https://www.kaggle.com/datasets/pgibiostat/pneumoniamnist-classification)을 `kagglehub`를 이용해 `data/`폴더에 저장하는 코드를 `01_inspect_data.py`로 생성해줘. 
>- 설치가 필요한 패키지가 있으면 먼저 무엇을 설치할지 알려 주고 나서 설치해 줘. 
>- 다운로드가 로그인·토큰 문제로 실패하면 임의의 다른 출처(예: 다른 사본이나 `medmnist` 패키지)로 바꾸지 말고, 오류와 필요한 조치를 알려 줘. 
>- 출력할 값 : (1) 받은 파일 이름과 위치, (2) `.npz`의 키 이름, (3) 각 배열의 shape과 자료형, (4) 학습·검증·시험별 레이블 0/1 개수
>- 그리고 학습 영상에서 레이블 0과 1의 예시를 각각 3장씩 레이블과 함께 그려 `outputs/examples.png`로 저장해 줘(화면 창은 띄우지 마)
>- 스크립트를 실행한 뒤 출력 결과를 요약해 줘. 이후 단계의 스크립트도 이 폴더에 번호를 붙여 만들 계획이다.

**참가자가 결과에서 확인할 것**

- 개수가 학습 3,883·검증 524·시험 624와 일치하는가? 일치하지 않으면 에이전트가 다른 데이터를 받은 것이 아닌지 먼저 의심한다. 예를 들어 MedMNIST 원본은 학습이 4,708장이다.
- 레이블 1이 폐렴이라는 설명이 Kaggle 데이터셋 설명과 맞는가? 에이전트의 서술만 믿지 말고 데이터셋 페이지와 대조한다.
- 영상 크기가 28×28이고 픽셀 값의 범위가 0~255인가?
- 시험 세트에서 폐렴 비율이 얼마인가? (약 62.5%인지 확인. 기준선 정확도 논의에 쓴다.)
- 에이전트가 설치한 패키지와 내려받은 위치를 스크립트나 대화에서 설명할 수 있는가?

**② 전처리 — 25분대**

>`01_inspect_data.py`가 받은 데이터로 학습·검증·시험 로더를 만드는 코드를 `02_prepare_data.py`로 생성해줘. 
>- 영상의 픽셀 범위와 레이블 모양을 먼저 확인해 줘. 
>- 영상은 `[0,1]`로 정규화하고 PyTorch 입력 모양 `[N, 1, 28, 28]`으로 바꿔 줘. 
>- 레이블은 `(N,1)`에서 정수형(long) `[N]`으로 펼쳐(squeeze) 줘. 
>- 제공된 학습·검증·시험 분할을 그대로 유지하고, 시험 자료는 최종 평가 전에 사용하지 말아 줘. 
>- 출력할 값 : (1) 정규화 후 픽셀의 최솟값·최댓값, (2) 세 로더의 건수, (3) 학습 로더 한 배치의 영상·레이블 shape과 자료형
>- 스크립트를 실행한 뒤 출력 결과를 요약해 줘. 

**참가자가 결과에서 확인할 것**

- 정규화 후 최솟값이 0, 최댓값이 1 이하인가? 정규화를 두 번 하거나 255로 나누지 않은 코드는 없는가?
- 배치 shape이 입력 `[64, 1, 28, 28]`, 레이블 `[64]`(정수형)로 나오는가? 마지막 배치는 64보다 작을 수 있다.
- 학습·검증·시험 로더의 건수 합이 3,883·524·624와 일치하는가? 제공된 분할을 에이전트가 다시 섞거나 나누지 않았는가?
- 학습 로더만 섞고(shuffle) 검증·시험 로더는 섞지 않았는가?
- 시험 로더가 이 단계에서 학습이나 통계 계산(평균·표준편차 등)에 쓰이지 않았는가?

**③ 모델·학습 — 40분대**

>`02_prepare_data.py`의 로더를 사용해 작은 CNN을 학습하는 코드를 `03_train.py`로 생성해줘. 
>- 합성곱 층 2개의 작은 CNN으로 만들고, CPU에서만 실행해 줘. 데이터나 모델을 GPU로 옮기는 코드는 넣지 말아 줘. 
>- 손실함수는 `CrossEntropyLoss`를 쓰고, 출력은 두 범주의 **logit 2개**, 레이블은 정수형 `[N]`으로 맞춰 줘. 
>- 학습 전에 모델·입력·레이블의 shape을 먼저 검사해 줘. 
>- 난수 시드를 고정하고 <진행자가 정한 epoch 수, 예: 8> epoch 학습해 줘. 
>- 출력할 값 : (1) 학습 전 손실, (2) epoch별 학습 손실과 검증 손실, (3) 전체 학습 시간
>- epoch별 학습·검증 손실을 그래프로 그려 `outputs/loss_curve.png`로 저장해 줘(화면 창은 띄우지 마)
>- 스크립트를 실행한 뒤 출력 결과를 요약해 줘. 

**참가자가 결과에서 확인할 것**

- 모델 출력이 `[N, 2]`(logit 2개)이고 손실이 `CrossEntropyLoss`인가? 출력에 softmax를 미리 적용해 넣지 않았는가?
- 학습 전(무작위 상태) 손실이 대략 0.69(= ln 2) 근처인가? 크게 벗어나면 출력이나 레이블 모양을 의심한다.
- epoch에 따라 학습 손실이 내려가는가? 검증 손실이 오르는 구간이 있는지, 있다면 몇 epoch부터인가?
- 매 epoch 안에서 검증 데이터로 가중치를 갱신하지 않았는가? (`model.eval()`과 `torch.no_grad()` 사용, 검증 단계에 `backward()` 없음)
- 코드에 GPU 사용 코드(`.cuda()`, `.to("cuda")`)가 없는가? 총 학습 시간은 리허설 시간과 비슷한가?

**④ 평가 — 75분대**

>`03_train.py`에서 학습한 모델을 시험 세트에서 평가하는 코드를 `04_evaluate.py`로 생성해줘. 
>- 지금까지 사용하지 않은 시험 세트에서만 최종 평가해 줘.

>- 출력할 값 : (1) 혼동행렬의 TP·FP·FN·TN, (2) 민감도와 특이도(각 식의 분모 명시), (3) 사진을 보지 않고 항상 ‘폐렴’이라고 답하는 기준선의 정확도, (4) 정확도, 필요하면 AUC
>- 거짓 음성과 거짓 양성 사례를 각각 2~3장씩 정답·예측과 함께 그려 `outputs/errors.png`로 저장해 줘(화면 창은 띄우지 마)
>- 결과를 진료 성능이라고 표현하지 말아 줘. 
>- 스크립트를 실행한 뒤 출력 결과를 요약해 줘. 

**참가자가 결과에서 확인할 것**

- 혼동행렬의 행·열 방향이 코드와 출력 표시에서 일치하는가? TP+FN=390(실제 폐렴), FP+TN=234(실제 정상)로 맞아떨어지는가?
- 민감도 = TP ÷ (TP+FN), 특이도 = TN ÷ (TN+FP)로 분모가 맞는가? 손으로 한 번 계산해 출력과 대조한다.
- 모델 정확도가 ‘항상 폐렴’ 기준선(62.5%)보다 얼마나 높은가? 정확도만 높고 특이도가 낮지 않은가?
- 예측 확률을 판정으로 바꾸는 기준값(0.5 등)이 무엇인가? 이 기준값을 시험 결과를 보고 정하지 않았는가?
- 오분류 그림의 제목(정답·예측)이 실제 레이블과 일치하는가? 그림 속 사례가 거짓 음성과 거짓 양성으로 올바르게 분류되어 있는가?

- 에이전트가 수정한 부분이 있다면 수정 이유를 자기 말로 설명할 수 있는가? 수정 뒤 시험 세트로 다시 평가하지 않았는가?
- 결과 설명에 ‘진단’, ‘임상 성능’ 같은 표현이 남아 있지 않은가?

### 6. 진행자가 던질 질문

- **영상 탐색:** 같은 폐렴 범주 안에서도 보이는 차이는 무엇인가? 28×28 이미지에서 사라진 정보는 무엇인가?
- **학습:** 학습 손실은 내려가는데 검증 손실이 올라가면 무슨 뜻인가? 이번 실행의 곡선에서 그런 구간이 있었는가?
- **불균형:** 항상 ‘폐렴’이라 답해도 정확도가 62.5%라면, 우리 모델의 정확도는 얼마나 의미가 있는가?
- **평가:** 거짓 음성과 거짓 양성 중 어느 사례를 우선 살펴보고 싶은가? 그 이유는 무엇인가?
- **에이전트 검토:** 에이전트가 제시한 높은 정확도만 보고 넘어가면 놓치기 쉬운 오류는 무엇인가?
- **연구 설계:** 이 모델을 다른 병원·성인 환자·다른 촬영 조건에 적용하려면 어떤 자료와 검증이 필요한가?

### 7. 시간 지연 시 진행 규칙

- **환경 설치나 다운로드가 안 되는 참가자:** 결과가 저장된 백업 스크립트와 저장된 실행 결과를 보며 개념을 따라오게 하고, 그 출력을 대상으로 프롬프트 ⑤(검토)를 실습하게 한다.
- **코딩 에이전트를 쓸 수 없는 참가자(계정·네트워크·사용량 한도):** 백업 스크립트를 단계별로 직접 실행하며 각 출력을 읽고, 진행자가 시연하는 에이전트 화면을 함께 본다. 이후 프롬프트는 옆 참가자와 묶어 한 대의 에이전트로 진행한다.
- **학습이 느린 참가자:** epoch를 줄이거나(단, 3 미만이면 곡선 해석은 진행자 예시로 대체) 학습 세트만 계층적으로 축소한다. 최종 평가용 시험 세트는 유지한다. 다른 참가자의 성능 수치와 순위를 비교하지 않는다.
- **모델 코드가 막힐 때:** 완성된 진행자용 백업 스크립트의 해당 단계부터 시작해, 에이전트에게 입력·출력 shape과 오류 원인을 설명하게 한다.
- **시간이 10분 이하 남았을 때:** 추가 성능 개선을 생략하고 반드시 혼동행렬과 거짓 음성 1건의 해석까지 진행한다.

### 8. 성과 확인

완료 기준은 정확도 점수가 아니다. 참가자가 스크립트와 저장된 그림·출력으로 다음을 남기면 완료로 본다: (1) 데이터 구조와 레이블의 의미, (2) 자신의 CNN과 학습·검증 그래프, (3) 시험 세트 혼동행렬·민감도·특이도와 ‘무조건 폐렴’ 기준선 비교, (4) 오분류 영상 1건에 대한 검토, (5) 모델의 적용 한계 두 가지. 평가 수치는 실행 환경과 학습 조건에 따라 달라질 수 있다.
