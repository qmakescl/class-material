모집단 평균에 대한 가설검정

VS Code에서 R 스크립트를 한 줄씩 실행하며 세 가지 t 검정을 해 본다. R이 내놓는 t, 자유도, p-value가 귀무가설 아래의 분포에서 어디에 놓이는지 그림으로 확인하고, 효과크기까지 구한다.

도구
R과 tidyverse, VS Code, R 확장, Google Antigravity 확장. 노트북 없이 .R 스크립트만 쓴다.
예제 데이터
식생활 교육 연구를 흉내 낸 연습용 가상 데이터. 48명의 교육 전·후 나트륨 섭취량(mg/일).
다루는 검정
단일표본, 독립표본(Welch·Student), 대응표본 t 검정
함수 도움말
코드에서 점선 밑줄이 있는 함수 이름에 마우스를 올리면(휴대폰은 누르면) 목적, 인수, 반환값이 나타난다.
효과크기
Cohen의 d, Hedges의 g, dz

1작업환경: VS Code에서 R 실행하기

스크립트 파일에 코드를 적고, 한 줄씩 R 터미널로 보내 실행한다. 막히는 곳은 VS Code 안의 AI 에이전트에게 묻는다. 아래 다섯 가지를 순서대로 설치한다.

  1. R 설치. cran.r-project.org에서 운영체제에 맞는 설치 파일을 받아 기본 옵션으로 설치한다. macOS는 프로세서(Apple silicon, Intel)에 맞는 파일을 고른다.
  2. VS Code 설치. code.visualstudio.com의 첫 화면에서 내려받기 버튼을 누르면 운영체제에 맞는 파일을 받는다.
    • Windows: 받은 설치 파일을 실행하고 기본 옵션으로 진행한다. "PATH에 추가" 항목은 체크된 그대로 둔다.
    • macOS: 받은 파일의 압축을 풀고 Visual Studio Code 앱을 응용 프로그램 폴더로 옮긴 다음 실행한다.
  3. R 확장 설치. VS Code 왼쪽의 확장(Extensions) 아이콘을 누르거나 Ctrl+Shift+X(macOS는 ⌘+Shift+X)를 누른다. R을 검색해 게시자가 REditorSupport인 확장을 설치한다.
  4. Google Antigravity 확장 설치. 같은 확장 화면에서 Google Antigravity를 검색해 게시자가 Google인 확장을 설치한다. 설치가 끝나면 왼쪽 막대에 생긴 Antigravity 아이콘을 눌러 Google 계정으로 로그인한다. 자세한 것은 아래 "AI 에이전트 연결하기"에서 다룬다.
  5. 패키지 설치. 아래 한 줄을 R에서 한 번만 실행한다. 패키지를 내려받는 저장소는 repos 인수로 https://cloud.r-project.org/를 지정한다. 저장소를 고르라는 창이 뜨지 않고, 가까운 서버로 자동 연결된다. languageserver는 VS Code가 자동완성과 도움말을 띄우는 데 쓴다. tidyverse는 데이터를 읽고 다듬고 그리는 패키지 묶음이고(Excel을 읽는 readxl도 함께 설치된다), writexl은 Excel 저장, effectsize는 효과크기 계산, extrafont는 그림에 한글 글꼴을 쓰는 데 쓴다. 설치에 몇 분 걸린다.
R · 처음 한 번만
install.packages(
  c("languageserver", "tidyverse", "writexl", "effectsize", "extrafont"),
  repos = "https://cloud.r-project.org/"
)

AI 에이전트 연결하기: Google Antigravity 확장

Google Antigravity는 Google의 AI 코딩 에이전트다. VS Code용 확장을 설치하면 편집기 옆에 에이전트 창이 생기고, 열어 둔 폴더의 파일을 읽고 고치는 일을 대화로 시킬 수 있다.

항목내용
확장 이름과 게시자Google Antigravity, 게시자 Google (식별자 Google.google-antigravity)
필요한 것VS Code 1.90 이상, Google 계정. 무료 요금제로도 쓸 수 있다.
운영체제Windows, macOS, Linux
  1. 확장 화면에서 Google Antigravity를 검색한다. 이름이 비슷한 확장이 여럿 나오므로 게시자가 Google인지 확인하고 설치(Install)를 누른다.
  2. 왼쪽 막대(Activity Bar)에 생긴 Antigravity 아이콘을 누른다.
  3. 안내에 따라 Google 계정으로 로그인한다. 브라우저가 열렸다가 VS Code로 돌아온다.
  4. 처음 실행할 때 확장이 에이전트 실행에 필요한 프로그램(agy)을 자동으로 내려받아 설치한다. 끝날 때까지 기다린다.
  5. 에이전트 창에 이 폴더에 어떤 파일이 있는지 알려줘처럼 한 줄을 보내 응답이 오는지 확인한다.

이 수업에서 AI에게 묻는 법

  • 오류를 풀 때. R 터미널의 오류 메시지를 그대로 붙여 넣고 실행한 코드를 함께 준다. 예: 01_ttest.R의 12번째 줄에서 이 오류가 난다. 원인과 고친 코드를 알려줘.
  • 코드를 읽을 때. 예: t.test(sodium_post ~ group, data = d)의 출력을 한 줄씩 설명해줘.
  • 내 데이터에 옮길 때. 예: dataset/raw/mydata.xlsx의 첫 시트를 tidyverse로 읽고, group 열로 score 열의 평균을 비교하는 Welch 검정 코드를 써줘.

AI가 준 답은 직접 실행해 확인한다. 에이전트는 없는 함수나 인자를 지어내기도 하고, 검정을 잘못 고르기도 한다. 어떤 검정을 쓸지, 가설의 방향을 어떻게 둘지, 결과를 어떻게 해석할지는 스스로 정하고 설명할 수 있어야 한다. 에이전트가 파일을 고치겠다고 하면 바뀌는 내용을 읽어 본 뒤 승인한다. 개인정보가 들어 있는 연구 데이터는 에이전트에게 보내도 되는지 먼저 확인한다.

폴더를 열고 스크립트를 실행한다

  1. 실습 폴더를 하나 만든다. 예: ttest-lab. VS Code에서 파일 → 폴더 열기로 이 폴더를 연다.
  2. 새 파일 01_ttest.R을 만든다. 확장자가 .R이어야 R 파일로 인식한다.
  3. 코드 한 줄에 커서를 두고 Ctrl+Enter(macOS는 ⌘+Enter)를 누른다. 아래쪽에 R 터미널이 열리고 그 줄이 실행된다. 여러 줄을 선택하고 누르면 선택한 부분이 실행된다.
  4. 그림은 VS Code 안의 그림 탭에 나타난다. View(d)를 실행하면 데이터가 표로 열린다.
  5. 데이터와 그림을 둘 폴더는 2장에서 코드로 만든다.

자주 막히는 곳. 파일 하나만 열지 말고 폴더를 연다. 폴더를 열면 R 터미널의 작업 폴더가 그 폴더가 되어 "dataset/raw/sodium.csv" 같은 상대 경로가 그대로 통한다. Windows에서 R 터미널이 열리지 않으면 VS Code 설정에서 r.rterm.windows에 R.exe의 경로를 적는다.

Windows: 터미널에서 R.exe를 바로 실행하게 하기

Windows용 R은 설치할 때 실행 파일의 위치를 PATH에 등록하지 않는다. R 확장은 R을 스스로 찾아 실행하므로 위의 방법은 그대로 되지만, VS Code의 일반 터미널(PowerShell)에 R.exe를 입력하면 찾을 수 없다는 오류가 난다. AI 에이전트가 터미널에서 스크립트를 실행하려 할 때도 같은 오류로 멈춘다. R의 bin 폴더를 PATH에 추가하면 해결된다. macOS는 이 설정이 필요 없다.

  1. bin 폴더의 경로 확인. R 터미널에서 아래 한 줄을 실행하면 경로가 나온다. 보통 C:\Program Files\R\R-4.x.x\bin 꼴이다. 따옴표 안의 경로를 복사하고, 역슬래시가 두 개씩(\\) 보이면 하나씩으로 고친다. 파일 탐색기에서 C:\Program Files\R 아래의 bin 폴더를 찾아 주소 표시줄의 경로를 복사해도 된다.
R
normalizePath(file.path(R.home(), "bin"))
  1. 환경 변수 창 열기. 시작 버튼을 누르고 환경 변수를 검색해 계정의 환경 변수 편집을 연다.
  2. Path에 추가. 위쪽 사용자 변수 목록에서 Path를 선택하고 편집을 누른다. 새로 만들기를 누르고 복사한 경로를 붙여 넣는다. 확인을 두 번 눌러 창을 닫는다.
  3. VS Code 다시 시작. VS Code 창을 모두 닫았다가 다시 연다. 바뀐 PATH는 새로 시작한 프로그램에만 적용된다.
  4. 확인. Ctrl+Shift+`로 터미널을 열고 아래 첫 줄을 입력한다. R의 버전이 나오면 된 것이다.
PowerShell · VS Code 터미널
R.exe --version              # 버전이 나오면 PATH 설정이 된 것이다
R.exe                        # R을 대화형으로 시작한다. 끝낼 때는 q()
Rscript.exe 01_ttest.R       # 스크립트 파일 전체를 실행한다

PowerShell에서는 R이 아니라 R.exe라고 적는다. PowerShell에서 r은 직전 명령을 다시 실행하는 내장 명령의 줄임말이어서, R만 입력하면 R이 시작되지 않는다.

R을 새 버전으로 올리면 설치 폴더 이름(R-4.x.x)이 바뀐다. Path에 넣은 경로도 새 폴더로 고친다.

2데이터 읽고 다듬기: tidyverse

데이터를 읽고, 다듬고, 그리는 일은 tidyverse로 한다. library(tidyverse) 한 줄이 파일을 읽는 readr, 표를 다루는 dplyr, 표의 모양을 바꾸는 tidyr, 그림을 그리는 ggplot2를 한꺼번에 불러온다.

tidyverse 코드는 파이프 %>%로 잇는다. 파이프는 왼쪽의 결과를 오른쪽 함수의 첫 번째 인수로 넘긴다. library(tidyverse)를 실행해야 쓸 수 있다. d %>% filter(group == "교육군")은 filter(d, group == "교육군")과 같고, "d를 가져와서, 교육군만 고른다"로 읽는다.

폴더 구조: 원본과 작업본을 나눈다

ttest-lab/ ├─ 01_ttest.R ├─ dataset/ │ ├─ raw/ 받은 원본 파일. 읽기만 하고 고치지 않는다 │ └─ working/ 다듬은 데이터. 코드로만 만든다 └─ output/ 그림 파일
R
dir.create("dataset/raw",     recursive = TRUE, showWarnings = FALSE)
dir.create("dataset/working", recursive = TRUE, showWarnings = FALSE)
dir.create("output",          showWarnings = FALSE)

원본 파일은 Excel로 열어 고치지 않는다. 고칠 것이 있으면 코드로 고치고 결과를 working에 저장한다. 이렇게 해 두면 데이터셋이 바뀌어도 새 파일을 raw에 넣고 스크립트를 다시 실행하는 것으로 끝난다. working과 output의 파일은 언제든 지우고 다시 만들 수 있다.

실습 파일 만들기

실제 연구에서는 받은 파일을 dataset/raw에 넣는 것으로 시작한다. 여기서는 연습용 데이터를 CSV와 Excel 두 형식으로 그 자리에 만들어 둔다. 48명 중 24명은 식생활 교육을 받았고(교육군), 24명은 받지 않았다(대조군). 두 집단 모두 사전과 사후에 하루 나트륨 섭취량을 쟀다.

read_csv()는 열마다 자료형을 추측해 알려 준다. glimpse()로 숫자여야 할 열이 문자(chr)로 읽히지 않았는지 확인한다.

한글이 깨질 때. read_csv()는 파일이 UTF-8이라고 가정한다. 공공데이터포털이나 오래된 Excel에서 저장한 CSV는 CP949인 경우가 많다. 이때는 read_csv("파일.csv", locale = locale(encoding = "CP949"))로 읽는다.

다듬어서 working에 저장하기

R
# 결측값이 있는지 열마다 센다
raw %>% summarise(across(everything(), ~ sum(is.na(.x))))

# 원본은 그대로 두고, 다듬은 결과를 d에 담는다
d <- raw %>%
  mutate(
    group = factor(group, levels = c("교육군", "대조군")),   # 수준의 순서를 직접 정한다
    diff  = sodium_pre - sodium_post                         # 양수면 섭취량이 줄었다
  )

# 집단별 사례 수
d %>% count(group)

# 집단별 평균과 표준편차
d %>%
  group_by(group) %>%
  summarise(
    n         = n(),
    pre_mean  = mean(sodium_pre),
    pre_sd    = sd(sodium_pre),
    post_mean = mean(sodium_post),
    post_sd   = sd(sodium_post)
  )

# 한 집단만 골라 내기
edu <- d %>% filter(group == "교육군")

# 사전·사후를 세로로 쌓은 긴 모양
d_long <- d %>%
  pivot_longer(
    c(sodium_pre, sodium_post),
    names_to = "time", names_prefix = "sodium_", values_to = "sodium"
  ) %>%
  mutate(time = factor(time, levels = c("pre", "post")))

# 다듬은 데이터를 working에 저장한다
write_csv(d,      "dataset/working/sodium_clean.csv")
write_csv(d_long, "dataset/working/sodium_long.csv")

수준의 순서가 차이의 부호를 정한다. t.test()는 첫 번째 수준에서 두 번째 수준을 뺀다. 위처럼 정하면 차이는 "교육군 − 대조군"이 된다. 순서를 정하지 않으면 R이 글자 순으로 정하므로 부호를 해석하기 전에 levels(d$group)을 확인한다.

표의 모양이 검정을 정한다. 독립표본 검정은 "집단 열 하나 + 값 열 하나"인 모양에서 값 ~ 집단 공식을 쓴다. 대응표본 검정은 같은 사람의 두 측정값이 한 행에 나란히 있는 모양에서 두 열을 짝지어 넣는다. d는 두 모양을 모두 갖추고 있다. 사전·사후를 한 그림에 그릴 때는 pivot_longer()로 만든 긴 모양 d_long을 쓴다.

CSV는 factor의 순서를 기억하지 못한다. working의 CSV를 다시 읽으면 group은 문자열로 돌아온다. 읽은 뒤 factor()를 다시 적용하거나, R 전용 형식으로 저장한다: write_rds(d, "dataset/working/sodium_clean.rds"), 읽을 때는 read_rds("dataset/working/sodium_clean.rds").

3검정의 논리: H0 아래의 분포와 p-value

세 가지 t 검정은 계산하는 재료만 다르고 논리는 같다.

  1. 귀무가설 H0와 대립가설 H1을 세운다. H1의 방향(양측, 한쪽)은 데이터를 보기 전에 정한다.
  2. 표본에서 검정통계량을 구한다. 관측한 값이 귀무가설의 값에서 표준오차의 몇 배만큼 떨어져 있는지를 잰 것이다.
  3. H0가 참이라면 이 통계량은 자유도 df인 t 분포를 따른다. 이 분포가 판단의 기준이 된다.
  4. p-value는 이 분포에서 관측한 t만큼, 또는 그보다 더 극단적인 값이 나올 확률이다. p-value가 유의수준 α보다 작으면 H0를 기각한다.
t = (추정값 − 귀무가설의 값) / 표준오차

아래에서 t와 자유도를 직접 움직여 본다. 파란 넓이가 p-value이고, 축 위의 주황 띠가 유의수준 α로 정한 기각역이다. 관측한 t가 주황 띠 안에 들어가는 것과 p < α는 같은 말이다.

p-value는 H0가 참일 확률이 아니다. H0가 참이라고 가정했을 때 이런 데이터가 나올 확률이다. 또 p-value는 차이가 얼마나 큰지 말해 주지 않는다. 표본이 크면 작은 차이도 유의하게 나온다. 그래서 효과크기를 함께 보고한다(Wasserstein & Lazar, 2016).

4단일표본 t 검정

질문. 참여자 48명의 사전 나트륨 섭취량 평균은 기준값과 다른가? 선행 조사에서 보고된 성인 평균이 3000 mg이라고 하고, 이 값을 기준으로 삼는다.

H₀: μ = 3000    H₁: μ ≠ 3000
t = (x̄ − μ₀) / (s / √n),   df = n − 1
R
x <- d %>% pull(sodium_pre)    # 열 하나를 벡터로 꺼낸다

# 가정 확인: 정규성. 점들이 직선을 따라가는지 본다
p_qq <- ggplot(d, aes(sample = sodium_pre)) +
  stat_qq() +
  stat_qq_line()
p_qq
ggsave("output/qq_sodium_pre.png", p_qq, width = 5, height = 5, dpi = 300)
shapiro.test(x)

# 검정
res1 <- t.test(x, mu = 3000)     # 기본값은 양측, 신뢰수준 95%
res1

# 결과에서 값만 꺼내기
res1$statistic   # t
res1$parameter   # df
res1$p.value
res1$conf.int

# 결과 전체를 한 행짜리 표로
broom::tidy(res1)

효과크기: Cohen의 d

평균이 기준값에서 표준편차의 몇 배만큼 떨어져 있는지를 나타낸다. 단위가 없어서 다른 연구와 비교할 수 있다.

d = (x̄ − μ₀) / s
R
d1 <- (mean(x) - 3000) / sd(x)
d1

# 같은 값을 패키지로, 신뢰구간과 함께
library(effectsize)
cohens_d(x, mu = 3000)

5독립표본 t 검정

질문. 교육이 끝난 뒤, 교육군의 나트륨 섭취량 평균은 대조군과 다른가? 두 집단은 서로 다른 사람들이다.

H₀: μ₁ = μ₂    H₁: μ₁ ≠ μ₂    (1 = 교육군, 2 = 대조군)
Welch:   t = (x̄₁ − x̄₂) / √(s₁²/n₁ + s₂²/n₂),   df는 Welch–Satterthwaite 근사
Student: t = (x̄₁ − x̄₂) / (sp √(1/n₁ + 1/n₂)),   df = n₁ + n₂ − 2

R의 t.test()는 두 집단의 분산이 같다고 가정하지 않는 Welch 검정을 기본으로 쓴다. 분산이 실제로 같을 때도 Welch 검정은 검정력을 거의 잃지 않고, 분산이 다를 때는 Student 검정보다 1종 오류를 잘 지킨다. 그래서 등분산 검정을 먼저 하고 고르는 대신 처음부터 Welch 검정을 쓰도록 권한다(Delacre et al., 2017).

R
# 집단별 기술통계와 분포
d %>%
  group_by(group) %>%
  summarise(n = n(), mean = mean(sodium_post), sd = sd(sodium_post))
p2     # 2장에서 그린 상자그림

# Welch 검정 (기본값)
res2 <- t.test(sodium_post ~ group, data = d)
res2
broom::tidy(res2)

# 등분산을 가정하는 Student 검정
t.test(sodium_post ~ group, data = d, var.equal = TRUE)

아래에서 Welch와 Student를 바꿔 본다. 이 데이터는 두 집단의 크기가 같아서 t 값은 변하지 않고 자유도만 46에서 41.5로 줄어든다. 분포의 꼬리가 조금 두꺼워지고 p-value가 조금 커진다.

효과크기: Cohen의 d와 Hedges의 g

두 평균의 차이를 합동 표준편차로 나눈다. 표본이 작으면 d가 모집단 값보다 조금 크게 나오므로, 보정 계수 J를 곱한 Hedges의 g를 함께 쓴다.

sp = √( ((n₁−1)s₁² + (n₂−1)s₂²) / (n₁+n₂−2) )
d = (x̄₁ − x̄₂) / sp,    g = d × J,   J = 1 − 3 / (4(n₁+n₂−2) − 1)
R
s <- d %>%
  group_by(group) %>%
  summarise(n = n(), m = mean(sodium_post), v = var(sodium_post))
s      # 첫 행이 교육군, 둘째 행이 대조군

sp <- sqrt(sum((s$n - 1) * s$v) / (sum(s$n) - 2))
d2 <- (s$m[1] - s$m[2]) / sp
J  <- 1 - 3 / (4 * (sum(s$n) - 2) - 1)
c(d = d2, g = d2 * J)

# 패키지로 확인
cohens_d(sodium_post ~ group, data = d)
hedges_g(sodium_post ~ group, data = d)

6대응표본 t 검정

질문. 교육군 24명의 나트륨 섭취량은 교육 전보다 교육 후에 달라졌는가? 같은 사람을 두 번 쟀으므로 두 측정값은 독립이 아니다.

대응표본 검정은 사람마다 차이 D = 사전 − 사후(2장에서 만든 diff 열)를 구한 다음, 차이의 평균이 0인지 보는 단일표본 검정이다. 사람마다 원래 많이 먹고 적게 먹는 차이는 뺄셈에서 사라지고 변화량만 남는다.

H₀: μD = 0    H₁: μD ≠ 0
t = D̄ / (sD / √n),   df = n − 1   (n은 쌍의 수)
R
edu <- d %>% filter(group == "교육군")    # diff 열은 2장에서 만들었다

# 가정 확인: 정규성을 보는 대상은 원자료가 아니라 차이다
ggplot(edu, aes(sample = diff)) +
  stat_qq() +
  stat_qq_line()
shapiro.test(edu$diff)
p3     # 2장에서 그린 사전·사후 변화 그림

# 검정
res3 <- t.test(edu$sodium_pre, edu$sodium_post, paired = TRUE)
res3

# 차이에 대한 단일표본 검정과 결과가 같다
t.test(edu$diff, mu = 0)

같은 자료에 독립표본 검정을 쓰면. t.test(edu$sodium_pre, edu$sodium_post)처럼 paired = TRUE를 빼고 실행해 본다. 평균 차이는 같은데 표준오차가 커져서 t가 작아진다. 사전과 사후가 강하게 상관되어 있을수록 대응표본 검정이 유리하다.

효과크기: dz와 dav

대응표본에서는 표준화에 쓰는 표준편차를 무엇으로 잡느냐에 따라 효과크기가 둘로 나뉜다. dz는 차이의 표준편차로 나눈 값이고 t / √n과 같다. 검정력 계산에 쓴다. dav는 두 시점 표준편차의 평균으로 나눈 값으로, 독립표본 연구의 d와 비교할 때 쓴다(Lakens, 2013). 어느 것을 보고했는지 반드시 밝힌다.

dz = D̄ / sD = t / √n,    dav = D̄ / ((s사전 + s사후) / 2)
R
edu %>%
  summarise(
    dz  = mean(diff) / sd(diff),
    dav = mean(diff) / ((sd(sodium_pre) + sd(sodium_post)) / 2),
    r   = cor(sodium_pre, sodium_post)      # 사전·사후 상관
  )

unname(res3$statistic) / sqrt(nrow(edu))    # dz와 같다

# 패키지로 확인 (dz)
cohens_d(edu$sodium_pre, edu$sodium_post, paired = TRUE)

한쪽 검정과 신뢰수준

대립가설의 방향은 alternative = "less" 또는 "greater"로, 신뢰수준은 conf.level = 0.99처럼 준다. 독립표본에서 "less"는 "첫 번째 수준의 평균이 더 작다"는 뜻이다. 실험판에서 방향을 바꾸면 R 호출문이 함께 바뀐다.

효과크기를 읽는 기준

Cohen(1988)은 d = 0.2를 작은 효과, 0.5를 중간 효과, 0.8을 큰 효과의 어림값으로 제시했다. 이 기준은 다른 근거가 없을 때 쓰는 출발점이다. 같은 분야의 선행 연구에서 보고된 효과크기, 그리고 mg 단위로 본 차이가 실제로 의미 있는 크기인지를 함께 놓고 해석한다.

보고에 넣을 것

집단별 평균과 표준편차, 검정통계량과 자유도, p-value, 평균 차이의 신뢰구간, 효과크기와 그 종류. 실험판 아래의 보고 문장이 이 순서를 따른다.
