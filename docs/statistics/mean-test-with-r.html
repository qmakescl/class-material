작업환경: VS Code에서 R 실행하기

스크립트 파일에 코드를 적고, 한 줄씩 R 터미널로 보내 실행한다. 막히는 곳은 VS Code 안의 AI 에이전트에게 묻는다. 아래 다섯 가지를 순서대로 설치한다. Windows에서는 4번과 5번 사이의 PATH 설정도 해 둔다.

  1. R 설치. cran.r-project.org에서 운영체제에 맞는 설치 파일을 받아 기본 옵션으로 설치한다. macOS는 프로세서(Apple silicon, Intel)에 맞는 파일을 고른다. 처음 설치한다면 아래를 펼쳐 그림과 함께 따라 한다.
    R 설치 방법 자세히 보기 (Windows · macOS)

    R은 운영체제에 따라 설치 파일이 다르다. 두 경우 모두 출발점은 같다.

    1. https://r-project.org에 접속해 왼쪽 메뉴의 CRAN(또는 본문의 download R)을 누른다.
    2. 내려받을 서버(미러) 목록이 나온다. 맨 위의 0-Cloud나 Korea 아래의 주소 중 하나를 고른다.
      • 2026년 9월 현재 대한민국에서 제공하는 Mirror Site 가 없어 다음의 기본 Repository 선택
      • 0-Cloud: https://cloud.r-project.org/
    3. 자기 운영체제에 맞는 링크를 누르고 아래 설명을 따른다.

    Windows

    1. Download R for Windows Click
    2. base Click
    3. 맨 위의 Download R-4.x.x for Windows를 눌러 설치파일을 받는다.
    4. 받은 파일을 실행한다. 설치 언어는 한국어를 고르고, 나머지는 기본값 그대로 다음을 눌러 끝낸다.
    5. 설치 위치(기본값 C:\Program Files\R\R-4.x.x)를 확인한다. 아래 "Windows: 터미널에서 R.exe를 바로 실행하게 하기"에서 쓴다.

    macOS

    1. 먼저 자기 Mac의 프로세서 종류를 확인한다. 화면 왼쪽 위 사과 메뉴 → 이 Mac에 관하여를 열고 아래 표와 맞춰 본다.
    2. Download R for macOS를 누른다.
    3. 표에서 확인한 프로세서 종류에 맞는 .pkg 파일을 받는다.
    4. 받은 파일을 실행하고 기본값 그대로 계속을 눌러 설치한다.
    화면에 나오는 것프로세서 종류받을 파일
    칩: Apple M1, M2, M3 …Apple silicon이름에 arm64가 있는 .pkg
    프로세서: … Intel …Intel이름에 x86_64가 있는 .pkg
    잘못 받기 쉬운 곳 macOS에서 프로세서 종류에 맞지 않는 파일을 받으면 설치는 되지만 패키지 설치에서 오류가 난다. 파일 이름의 arm64와 x86_64를 꼭 확인한다.

    설치 확인

    설치된 R 프로그램을 실행한다(Windows: 시작 메뉴의 R, macOS: 응용 프로그램의 R). 창이 뜨면 다음 코드를 입력해 버전이 출력되는지 본다.

    R
    R.version.string
  2. VS Code 설치. code.visualstudio.com의 첫 화면에서 내려받기 버튼을 누르면 운영체제에 맞는 파일을 받는다.
    • Windows: 받은 설치 파일을 실행하고 기본 옵션으로 진행한다. "PATH에 추가" 항목은 체크된 그대로 둔다.
    • macOS: 받은 파일의 압축을 풀고 Visual Studio Code 앱을 응용 프로그램 폴더로 옮긴 다음 실행한다.
    VS Code 화면 구성 살펴보기

    Visual Studio Code(이후 VS Code로 지칭)의 화면은 아래 여섯 영역으로 이루어진다. VS Code 공식 문서를 ChatGPT로 번역한 것이다(원문).

    • 편집기(Editor) - 파일 내용을 작성하고 수정하는 중심 공간이다. 여러 파일을 위아래 또는 좌우로 나란히 열어 놓고 작업할 수 있다.
    • 기본 사이드바(Primary Side Bar) - 프로젝트 작업을 도와주는 여러 화면이 표시되는 공간이다. 파일과 폴더를 살펴보는 탐색기(Explorer) 등이 여기에 있다.
    • 보조 사이드바(Secondary Side Bar) - 기본 사이드바의 반대쪽에 있는 공간이다. 처음에는 채팅(Chat) 화면이 표시된다. 기본 사이드바에 있는 화면을 끌어다 놓아 보조 사이드바로 옮길 수 있다.
    • 상태 표시줄(Status Bar) - 현재 열려 있는 프로젝트와 편집 중인 파일의 상태 정보를 보여주는 영역이다.
    • 활동 표시줄(Activity Bar) - 화면의 가장 왼쪽에 있는 세로 막대다. 탐색기, 검색, 소스 제어 등의 화면을 전환할 때 사용한다. Git을 사용한다면 아직 서버로 보내지 않은 변경 사항의 개수와 같은 정보도 표시한다. 활동 표시줄을 마우스 오른쪽 버튼으로 클릭하면 위치를 변경할 수 있다.
    • 패널(Panel) - 편집기 아래쪽에 있는 추가 작업 공간이다. 기본적으로 프로그램 실행 결과, 디버깅 정보, 오류와 경고, 내장 터미널 등이 표시된다. 세로 공간을 더 넓게 사용하고 싶다면 패널을 화면의 왼쪽이나 오른쪽으로 옮길 수도 있다.
  3. R 확장 설치. VS Code 왼쪽의 확장(Extensions) 아이콘을 누르거나 Ctrl+Shift+X(macOS는 ⌘+Shift+X)를 누른다. R을 검색해 게시자가 REditorSupport인 확장을 설치한다.
    R 확장 설치 방법 자세히 보기
    1. VS Code를 실행한다.
    2. 활동 표시줄(Activity Bar)에서 다섯 번째에 있는 Extensions 아이콘을 누른다.
    3. 위쪽 검색창에 R을 입력하고 엔터 키를 눌러 검색한다.
    4. 잠시 후 나오는 목록에서 R의 Install을 눌러 설치한다. 확장 프로그램을 만든 제작자를 믿고 설치할 것인지 묻는 질문에는 Trust Publisher & Install을 누르면 확장 프로그램이 설치된다.
    5. 설치 후 활동 표시줄에 R 확장 프로그램 아이콘이 생겼는지 확인한다.
  4. Google Antigravity 확장 설치. 같은 확장 화면에서 Google Antigravity를 검색해 게시자가 Google인 확장을 설치한다. 설치가 끝나면 왼쪽 막대에 생긴 Antigravity 아이콘을 눌러 Google 계정으로 로그인한다. 설치부터 응답 확인까지의 순서는 아래를 펼쳐 본다.
    Antigravity 확장 설치와 연결 자세히 보기

    Google Antigravity는 Google의 AI 코딩 에이전트다. VS Code용 확장을 설치하면 편집기 옆에 에이전트 창이 생기고, 열어 둔 폴더의 파일을 읽고 고치는 일을 대화로 시킬 수 있다.

    필요한 것VS Code 1.90 이상, Google 계정. 무료 요금제로도 쓸 수 있다.
    운영체제Windows, macOS, Linux
    1. Extensions 항목에서 Antigravity를 검색한다. 이름이 비슷한 확장이 여럿 나오므로 아래 화면처럼 배포자가 Google인지 확인한 뒤 설치(Install)를 눌러 확장 프로그램을 설치한다.

Windows: 터미널에서 R.exe를 바로 실행하게 하기

Windows용 R은 설치할 때 실행 파일의 위치를 PATH에 등록하지 않는다. R 확장은 R을 스스로 찾아 실행하므로 2장에서 다루는 Ctrl+Enter 실행은 이 설정 없이도 되지만, VS Code의 일반 터미널(PowerShell)에 R.exe를 입력하면 찾을 수 없다는 오류가 난다. AI 에이전트가 터미널에서 스크립트를 실행하려 할 때도 같은 오류로 멈춘다. R의 bin 폴더를 PATH에 추가하면 해결된다. macOS는 이 설정이 필요 없다.

  1. R 실행. Windows+S를 누르면 나오는 아래쪽 검색창에 R을 입력해 R 실행 아이콘을 찾고, 눌러서 실행한다.
  2. bin 폴더의 경로 확인. R이 열리면 Console 창에서 아래 한 줄을 실행하고, 결과로 나온 문자열을 따옴표는 빼고 복사한다. R을 설치한 폴더에서 실행 파일들이 있는 bin 폴더의 전체 경로다. 보통 C:\Program Files\R\R-4.x.x\bin 꼴이다. 역슬래시가 두 개씩(\\) 보이는 것은 R이 문자열을 표시하는 방식이다. 아래 7번 그림처럼 그대로 붙여 넣어도 되고, 하나씩으로 고쳐도 된다. 파일 탐색기에서 C:\Program Files\R 아래의 bin 폴더를 찾아 주소 표시줄의 경로를 복사해도 된다.
    R
    normalizePath(file.path(R.home(), "bin"))
  3. 환경 변수 편집 항목 찾기. Windows+S를 누르면 나오는 아래쪽 검색창에서 환경변수를 검색하고, 나타나는 시스템 환경 변수 편집을 누른다. 관리자 암호를 묻거나 열리지 않으면 바로 아래의 계정의 환경 변수 편집을 누른다. 이때는 환경 변수 창이 바로 열리므로 4번을 건너뛴다.
  4. 환경 변수 창 열기. 시스템 속성 창 아래쪽의 환경 변수를 누른다.
  5. Path 찾기. 위쪽 사용자 변수 목록에서 Path를 찾아 누르고 편집을 누른다.
  6. 새 값 추가. 오른쪽 위의 새로 만들기를 눌러 환경 변수 Path에 새로운 값을 추가한다.
  7. 경로 붙여 넣기. 앞서 R에서 복사한 값을 붙여 넣고(①), 아래쪽의 확인을 누른다(②). 남아 있는 환경 변수 창과 시스템 속성 창도 확인을 눌러 닫는다.
  8. 확인. VS Code를 열고 터미널을 활성화한 뒤(Ctrl+Shift+`) R.exe를 입력하고 실행하면 R Console로 들어간다. VS Code가 이미 열려 있었다면 창을 모두 닫았다가 다시 연다. 바뀐 PATH는 새로 시작한 프로그램에만 적용된다. R을 끝낼 때는 q()를 입력한다.

터미널에서 쓰는 명령은 아래와 같다. 첫 줄에서 R의 버전이 나오면 PATH 설정이 된 것이다. VS Code의 터미널은 열어 둔 폴더(프로젝트 루트)에서 시작하므로, 스크립트는 scripts/를 붙여 가리킨다. 스크립트 파일은 2장 "폴더를 열고 스크립트를 실행한다"에서 만든다.

PowerShell · VS Code 터미널
R.exe --version                               # 버전이 나오면 PATH 설정이 된 것이다
R.exe                                         # R을 대화형으로 시작한다. 끝낼 때는 q()
Rscript.exe scripts/02.prepare_datasets.R     # 프로젝트 루트에서, 스크립트 파일 전체를 실행한다

PowerShell에서는 R이 아니라 R.exe라고 적는다. PowerShell에서 r은 직전 명령을 다시 실행하는 내장 명령의 줄임말이어서, R만 입력하면 R이 시작되지 않는다.

R을 새 버전으로 올리면 설치 폴더 이름(R-4.x.x)이 바뀐다. Path에 넣은 경로도 새 폴더로 고친다.

  1. 패키지 설치. 아래 한 줄을 R에서 한 번만 실행한다. 패키지를 내려받는 저장소는 repos 인수로 https://cloud.r-project.org/를 지정한다. 저장소를 고르라는 창이 뜨지 않고, 가까운 서버로 자동 연결된다. languageserver는 VS Code가 자동완성과 도움말을 띄우는 데 쓴다. tidyverse는 데이터를 읽고 다듬고 그리는 패키지 묶음이고(Excel을 읽는 readxl도 함께 설치된다), writexl은 Excel 저장, effectsize는 효과크기 계산, extrafont는 그림에 한글 글꼴을 쓰는 데 쓴다. 설치에 몇 분 걸린다.
R · 처음 한 번만
install.packages(
  c("languageserver", "tidyverse", "writexl", "effectsize", "extrafont"),
  repos = "https://cloud.r-project.org/"
)

이 수업에서 AI에게 묻는 법

  • 오류를 풀 때. R 터미널의 오류 메시지를 그대로 붙여 넣고 실행한 코드를 함께 준다. 예: scripts/03.ttest.R의 12번째 줄에서 이 오류가 난다. 원인과 고친 코드를 알려줘.
  • 코드를 읽을 때. 예: t.test(sodium_post ~ group, data = d)의 출력을 한 줄씩 설명해줘.
  • 내 데이터에 옮길 때. 예: dataset/raw/mydata.xlsx의 첫 시트를 tidyverse로 읽고, group 열로 score 열의 평균을 비교하는 Welch 검정 코드를 써줘.

AI가 준 답은 직접 실행해 확인한다. 에이전트는 없는 함수나 인자를 지어내기도 하고, 검정을 잘못 고르기도 한다. 어떤 검정을 쓸지, 가설의 방향을 어떻게 둘지, 결과를 어떻게 해석할지는 스스로 정하고 설명할 수 있어야 한다. 에이전트가 파일을 고치겠다고 하면 바뀌는 내용을 읽어 본 뒤 승인한다. 개인정보가 들어 있는 연구 데이터는 에이전트에게 보내도 되는지 먼저 확인한다.

R 확장 안에 함께 들어 있어서, Yes를 누르면 그것을 내 R에 설치한다. sess가 쓰는 다른 패키지가 없으면 그것은 R의 저장소에서 내려받으므로 인터넷에 연결되어 있어야 한다. 한 번 설치하면 다시 묻지 않고, R 확장이 새 버전으로 바뀌면 갱신할지 다시 물을 수 있다. 그때도 Yes를 누른다.

# 전체 행 수(n)와 서로 다른 참여자 번호의 수(n_id)를 구한다. 둘이 같으면 겹치는 사람이 없다
raw %>% summarise(n = n(), n_id = n_distinct(id))

# 결측값이 있는지 열마다 센다
# across(everything(), ...)는 모든 열에 같은 계산을 적용하고, .x 자리에 각 열이 들어간다
# is.na()는 결측이면 TRUE를 돌려주고, sum()은 TRUE의 개수를 센다
raw %>% summarise(across(everything(), ~ sum(is.na(.x))))

행과 열의 수, 열 이름, 앞뒤 몇 행을 눈으로 본다. 자료형은 위에서 glimpse()로 확인했다. count(raw, group)과 raw %>% count(group)은 적는 방법만 다르고 결과가 같다. 파이프로 적으면 "raw를 가져와서, 집단별로 센다"처럼 왼쪽에서 오른쪽으로 읽히고, 뒤에 다른 단계를 이어 붙이기 쉽다. 참여자 번호가 겹치는지와 결측의 개수도 여기서 센다. 같은 사람이 두 번 들어 있으면 뒤의 모든 계산이 틀어진다.

검정의 논리: \(H_0\) 아래의 분포와 p-value

세 가지 t 검정은 계산하는 재료만 다르고 논리는 같다. 이 문서에서는 영가설(귀무가설이라고도 한다)과 대안가설(대립가설이라고도 한다)이라는 용어를 쓴다.

  1. 영가설 \(H_0\)와 대안가설 \(H_1\)을 세운다. \(H_1\)의 방향(양측, 한쪽)은 데이터를 보기 전에 정한다.
  2. 표본에서 검정통계량을 구한다. 관측한 값이 영가설의 값에서 표준오차의 몇 배만큼 떨어져 있는지를 잰 것이다.
  3. \(H_0\)가 참이라면 이 통계량은 자유도 df인 t 분포를 따른다. 이 분포가 판단의 기준이 된다.
  4. p-value는 이 분포에서 관측한 t만큼, 또는 그보다 더 극단적인 값이 나올 확률이다. p-value가 유의수준 \(\alpha\)보다 작으면 \(H_0\)를 기각한다.
\[t = \frac{\text{추정값} - \text{영가설의 값}}{\text{표준오차}}\]

아래에서 t와 자유도를 직접 움직여 본다. 파란 넓이가 p-value이고, 축 위의 주황 띠가 유의수준 \(\alpha\)로 정한 기각역이다. 관측한 t가 주황 띠 안에 들어가는 것과 \(p < \alpha\)는 같은 말이다.

p-value는 \(H_0\)가 참일 확률이 아니다. \(H_0\)가 참이라고 가정했을 때 이런 데이터가 나올 확률이다. 또 p-value는 차이가 얼마나 큰지 말해 주지 않는다. 표본이 크면 작은 차이도 유의하게 나온다. 그래서 효과크기를 함께 보고한다(Wasserstein & Lazar, 2016).

독립표본 t 검정

질문. 교육이 끝난 뒤, 교육군의 나트륨 섭취량 평균은 대조군과 다른가? 두 집단은 서로 다른 사람들이다.

\[H_0: \mu_1 = \mu_2 \qquad H_1: \mu_1 \neq \mu_2 \qquad (1 = \text{교육군},\ 2 = \text{대조군})\] \[\text{Welch:}\quad t = \frac{\bar{x}_1 - \bar{x}_2}{\sqrt{s_1^2/n_1 + s_2^2/n_2}}, \qquad \mathit{df}\text{는 Welch–Satterthwaite 근사}\] \[\text{Student:}\quad t = \frac{\bar{x}_1 - \bar{x}_2}{s_p\sqrt{1/n_1 + 1/n_2}}, \qquad \mathit{df} = n_1 + n_2 - 2\]

두 식은 표준오차를 구하는 방법이 다르다. Welch 검정은 집단마다의 표본분산 \(s_1^2\), \(s_2^2\)를 따로 쓴다. Student 검정은 두 집단의 모분산이 같다고 가정하고, 두 표본분산을 하나로 합친 \(s_p\)를 쓴다.

Student 검정의 \(s_p\): 합동 표준편차

\(s_p\)는 합동 표준편차(pooled standard deviation)다. 두 집단의 모분산이 같은 값 \(\sigma^2\)이라면 \(s_1^2\)과 \(s_2^2\)은 둘 다 그 \(\sigma^2\)을 추정한 값이다. 그러니 둘을 합쳐 하나의 더 나은 추정값을 만들 수 있다. 각 표본분산에 그 자유도(\(n - 1\))를 곱해 더하고 전체 자유도로 나눈 것이 합동분산 \(s_p^2\)이고, 그 제곱근이 \(s_p\)다.

\[s_p^2 = \frac{(n_1-1)s_1^2 + (n_2-1)s_2^2}{n_1+n_2-2}, \qquad s_p = \sqrt{s_p^2}\]

표본이 큰 집단의 분산이 더 큰 가중치를 받는 가중평균이다. 두 집단의 크기가 같으면 두 표본분산의 단순 평균이 된다. 이 데이터에서는 \(s_1^2 = 285751\), \(s_2^2 = 566613\)이고 두 집단이 24명씩이므로 \(s_p^2 = 426182\), \(s_p = 652.8\)이다. 두 표준편차 534.6과 752.7의 사이에 있다. Student 검정의 표준오차는 \(s_p\sqrt{1/n_1 + 1/n_2} = 188.45\)가 된다. \(s_p\)는 아래 효과크기(Cohen의 d)에서도 다시 쓴다.

어느 검정을 쓸까: Welch 권고와 SPSS의 절차

R의 t.test()는 두 집단의 분산이 같다고 가정하지 않는 Welch 검정을 기본으로 쓴다. 분산이 실제로 같을 때도 Welch 검정은 검정력을 거의 잃지 않고, 분산이 다를 때는 Student 검정보다 1종 오류를 잘 지킨다. 그래서 등분산 검정을 먼저 하고 고르는 대신 처음부터 Welch 검정을 쓰도록 권한다(Delacre et al., 2017).

한편 SPSS에서 독립표본 t 검정을 실행하면 두 집단의 분산이 같은지에 대한 검정(Levene의 등분산 검정) 결과가 함께 나오고, 그 결과를 보고 "등분산을 가정함"과 "등분산을 가정하지 않음" 두 줄 가운데 하나를 읽는다. 이 장에서는 SPSS로 익힌 사람에게 익숙한 이 절차를 R에서 따라 해 본다. 먼저 두 집단의 분산을 검정하고, 그 결과에 따라 Student 검정이나 Welch 검정을 고른다. 다만 SPSS가 쓰는 것은 Levene 검정이고 여기서 쓰는 var.test()는 F 검정이어서, 절차는 같지만 검정 자체는 같지 않다.

1단계: 등분산 검정 var.test()

var.test()는 두 집단의 분산의 비에 대한 F 검정이다. 영가설은 "두 모분산의 비가 1이다"이고, 대안가설은 "비가 1이 아니다"이다. 비가 1이라는 것은 두 분산이 같다는 것과 같은 말이지만, 이 검정이 직접 다루는 대상은 분산의 차이가 아니라 비다. 그래서 R의 출력도 true ratio of variances is not equal to 1이라고 적고, 추정값과 신뢰구간도 분산의 비로 내놓는다.

\[H_0: \frac{\sigma_1^2}{\sigma_2^2} = 1 \qquad H_1: \frac{\sigma_1^2}{\sigma_2^2} \neq 1 \qquad (1 = \text{교육군},\ 2 = \text{대조군})\] \[F = \frac{s_1^2}{s_2^2}, \qquad \mathit{df} = (n_1 - 1,\ n_2 - 1)\]

검정통계량 F는 두 표본분산의 비다. 영가설이 참이면 F는 분자의 자유도가 \(n_1 - 1\), 분모의 자유도가 \(n_2 - 1\)인 F 분포를 따른다. 표본분산의 비가 1에서 멀수록, 곧 F가 1보다 훨씬 크거나 훨씬 작을수록 영가설과 어긋난다.

효과크기: Cohen의 d와 Hedges의 g

두 평균의 차이를 위에서 본 합동 표준편차 \(s_p\)로 나눈다. 표본이 작으면 d가 모집단 값보다 조금 크게 나오므로, 보정 계수 J를 곱한 Hedges의 g를 함께 쓴다.

\[s_p = \sqrt{\frac{(n_1-1)s_1^2 + (n_2-1)s_2^2}{n_1+n_2-2}}\] \[d = \frac{\bar{x}_1 - \bar{x}_2}{s_p}, \qquad g = d \times J, \qquad J = 1 - \frac{3}{4(n_1+n_2-2) - 1}\]
R
s <- d %>%
  group_by(group) %>%
  summarise(n = n(), m = mean(sodium_post), v = var(sodium_post))
s      # 첫 행이 교육군, 둘째 행이 대조군

sp <- sqrt(sum((s$n - 1) * s$v) / (sum(s$n) - 2))
d2 <- (s$m[1] - s$m[2]) / sp
J  <- 1 - 3 / (4 * (sum(s$n) - 2) - 1)
c(d = d2, g = d2 * J)

# 패키지로 확인
cohens_d(sodium_post ~ group, data = d)

대응표본 t 검정

질문. 교육군 24명의 나트륨 섭취량은 교육 전보다 교육 후에 달라졌는가? 같은 사람을 두 번 쟀으므로 두 측정값은 독립이 아니다.

대응표본 검정은 사람마다 차이 \(D = \text{사전} - \text{사후}\)(3장에서 만든 diff 열)를 구한 다음, 차이의 평균이 0인지 보는 단일표본 검정이다. 사람마다 원래 많이 먹고 적게 먹는 차이는 뺄셈에서 사라지고 변화량만 남는다.

\[H_0: \mu_D = 0 \qquad H_1: \mu_D \neq 0\] \[t = \frac{\bar{D}}{s_D/\sqrt{n}}, \qquad \mathit{df} = n - 1 \quad (n\text{은 쌍의 수})\]

효과크기: \(d_z\)와 \(d_{av}\)

대응표본에서는 표준화에 쓰는 표준편차를 무엇으로 잡느냐에 따라 효과크기가 둘로 나뉜다. \(d_z\)는 차이의 표준편차로 나눈 값이고 \(t/\sqrt{n}\)과 같다. 검정력 계산에 쓴다. \(d_{av}\)는 두 시점 표준편차의 평균으로 나눈 값으로, 독립표본 연구의 d와 비교할 때 쓴다(Lakens, 2013). 어느 것을 보고했는지 반드시 밝힌다.

\[d_z = \frac{\bar{D}}{s_D} = \frac{t}{\sqrt{n}}, \qquad d_{av} = \frac{\bar{D}}{(s_{\text{사전}} + s_{\text{사후}})/2}\]

한쪽 검정과 신뢰수준

대안가설의 방향은 alternative = "less" 또는 "greater"로, 신뢰수준은 conf.level = 0.99처럼 준다. 독립표본에서 "less"는 "첫 번째 수준의 평균이 더 작다"는 뜻이다. 실험판에서 방향을 바꾸면 R 호출문이 함께 바뀐다.

효과크기를 읽는 기준

Cohen(1988)은 \(d = 0.2\)를 작은 효과, 0.5를 중간 효과, 0.8을 큰 효과의 어림값으로 제시했다. 이 기준은 다른 근거가 없을 때 쓰는 출발점이다. 같은 분야의 선행 연구에서 보고된 효과크기, 그리고 mg 단위로 본 차이가 실제로 의미 있는 크기인지를 함께 놓고 해석한다.
