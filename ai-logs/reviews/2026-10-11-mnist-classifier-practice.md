- [ ] **직접 적은 숫자가 맞는가. (AI 확인)** 파라미터 계산(50,890 / 160 + 4,640 + 8,010 = 12,810), 층마다의 모양(26, 13, 11, 5, 800), 1에폭 = 540회 반복, 훈련 자료의 숫자별 장 수는 PyTorch로 실제 모형을 만들어 출력해 대조했다.
- [ ] **과적합 설명이 기록과 맞는가. (AI 확인)** 시드 42에서는 두 모형 모두 마지막 에폭의 검증 손실이 가장 낮다(30 / 30, 15 / 15). 실습의 30에폭 안에서는 검증 손실이 다시 오르지 않는다. 그래서 04는 실습 기록에 대해서는 "훈련 손실이 내려가는 만큼 검증 손실이 따라 내려가지 않는다"고만 쓰고, "오래 학습하면 다시 오른다"는 모형 ①을 같은 출발점에서 100에폭까지 학습한 실제 기록(그림의 셋째 단추)으로 보였다. 이 구성이 괜찮은가.
- [ ] **"검증 손실이 가장 낮았던 에폭의 가중치를 남긴다"가 헷갈리지 않는가.** 실습에서는 그 에폭이 마지막 에폭이라, 수강생의 결과에서도 마지막 에폭이 뽑힐 가능성이 크다. 절차의 뜻이 100에폭 그림으로 충분히 전해지는가.
- [ ] **사진 밀기 실험의 해석이 받아들일 만한가.** 05는 "펼치면 이웃 관계가 사라진다"의 근거로, 07은 "합성곱도 많이 밀면 무너진다, 훈련 사진의 숫자가 가운데에 놓여 있었기 때문"으로 썼다. 원인을 이렇게 단정해도 되는가.
- [ ] **필터 설명이 그림과 맞는가. (AI 확인)** 05의 필터 번호는 본문에 직접 적지 않고, 학습된 값에서 "위가 양·아래가 음", "그 반대", "왼쪽이 양·오른쪽이 음"이 가장 뚜렷한 필터를 골라 채운다. 시드 42에서는 15번(획의 아래쪽 가장자리), 8번(위쪽 가장자리), 16번(오른쪽 가장자리)이고, 세 필터를 숫자 7에 적용한 화면이 설명과 맞는 것을 확인했다. 다른 숫자에서도 그렇게 읽히는지 눌러 본다.

## 3. 실습이 실제로 되는가

- [ ] **Antigravity가 작업 폴더의 `AGENTS.md`를 규칙으로 읽는가. (직접 확인)** 00은 "Antigravity는 작업 폴더의 `AGENTS.md`를 규칙(rule)으로 읽어, 대화를 새로 시작해도 같은 약속을 적용한다"고 썼다. AI는 Antigravity에서 이것을 확인하지 못했다. 프롬프트 0이 약속을 요약하게 해서 읽었는지 드러나게 했으니, 요약이 맞게 나오는지와 대화를 새로 열어도 지켜지는지 본다. 파일을 두는 자리나 이름이 다르면 00의 안내 문장과 확인표를 고친다.
- [ ] **프롬프트 0~6을 Antigravity에서 차례로 실행해 본다. (직접 확인)** AI는 프롬프트를 에이전트에 넣어 보지 못했다. 대신 프롬프트가 요구하는 코드 경로(torchvision으로 읽기, 54,000 / 6,000 분할, 묶음의 모양, 두 모형의 층별 모양과 파라미터, 학습 1에폭)를 PyTorch 2.11.0 · torchvision 0.26.0에서 직접 돌려 '확인할 것'의 값과 같음을 확인했다.
- [ ] **에이전트가 한 단계씩만 하는가. (직접 확인)** `AGENTS.md`의 "시킨 단계만 한다"를 지키지 않고 앞서 나가는지 본다.
- [ ] **에이전트가 시드를 42로 쓰는가. (직접 확인)** 만든 스크립트에서 `42`를 찾아본다. 자료 나누기, `torch.manual_seed`, 섞기에 쓰였는지.
- [ ] **걸리는 시간. (직접 확인)** 이 문서를 만든 컴퓨터(Apple Silicon, CPU)에서 같은 코드 경로로 재면 모형 ①은 1에폭 약 1.4초(30에폭 약 40초), 모형 ②는 1에폭 약 6.5초(15에폭 약 1분 40초)다. 수업에 쓸 컴퓨터에서 재 보고, 길면 에폭 수를 줄인다(스크립트의 `EPOCHS`와 프롬프트 3·4를 함께 고친다).

- [ ] **Windows에서 `uv add torch torchvision matplotlib`. (직접 확인)** 설치 시간과 용량.
- [ ] **각자의 결과가 페이지와 다를 때.** 00의 안내("소수 둘째 자리쯤의 차이는 정상, 정확도가 90%에 못 미치면 설정을 대조")로 충분한가.
