## AI 응답 요약

원인이 `.ck li`의 `display: grid` 사용이라고 보고했다. CSS 그리드에서는 인라인
요소(`<strong>`, `<span>`)가 각각 별개의 그리드 아이템이 되고, 익명 래핑은 **연속된
텍스트 런에만** 적용된다. 그래서 2열 그리드에 아이템이 3~5개 생겨 항목 본문이 다음
행으로 흩어지고 있었다. 점검표 25개 항목 중 **24개**가 영향을 받았다. `li`를 일반
블록 + 내어쓰기(hanging indent)로 바꿔 인라인 내용이 하나의 텍스트 흐름을 유지하게
수정했고, HTML 마크업은 건드리지 않았다고 안내했다.

## 수행 작업

### 원인 분석

- `.ck li { display: grid; grid-template-columns: 20px 1fr; gap: 10px; }`
- 그리드 아이템이 되는 것: `::before`(☐) + 각 인라인 요소 + 연속 텍스트 런 묶음
- 예: `<li>대상자를 <strong>극단값 기준으로 선발</strong>했는가? (…)</li>`
  → ☐ / "대상자를 " / `<strong>` / "했는가? (…)" = **아이템 4개**. 2열이므로 2행으로
  나뉘어 문장이 표처럼 쪼개진다.
- 항목별 아이템 수를 전수 계산한 결과 2개(정상)인 항목은 1개뿐이고 나머지 24개가
  3~5개였다. `<span class="future">`("앞으로 배울 내용")가 붙은 항목이 5개로 가장 심했다.

### 수정

```css
/* 항목 본문에 <strong>·<span>이 섞여 있어 li 를 그리드로 만들면 인라인 요소마다
   별개의 그리드 아이템이 되어 줄이 깨진다. 내어쓰기(hanging indent)로 처리한다. */
.ck li { position: relative; padding-left: 28px; font-size: 14.5px; }
.ck li::before { content: "☐"; position: absolute; left: 0; top: 0; color: var(--accent); font-weight: 700; }
```

- `li`가 일반 블록이 되어 인라인 내용이 한 흐름으로 이어지고, 두 번째 줄부터도 28px
  위치에 정렬된다(그리드로 의도했던 시각적 결과와 동일).
- `padding-left: 28px`는 기존 `20px` 열 + `10px` 간격과 비슷한 폭으로 맞췄다.
- `.ck` 컨테이너(`flex-direction: column; gap: 9px`)와 HTML `<li>` 25개는 그대로 두었다.
- 왜 이렇게 고쳤는지 알 수 있도록 CSS에 주석을 남겼다.
